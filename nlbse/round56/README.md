# Окно по найденному участку и окно по центру

Обе схемы используют компактный энкодер раунда 38 и одинаковый список функций. Дополнительное окно разрешено при фактическом отрицательном ответе сканера, отрицательном итоговом отступе в интервале (−3,8; 0] и длине функции больше 64 токенов. Каждое окно содержит 62 токена исходного текста и два служебных. В первом варианте окно ставится по центру функции, во втором — вокруг максимума токенной головы с архивной разметкой из раунда 55. В обоих случаях используется одна общая логистическая калибровка по исходному отступу, оценке vulnerability и `W` из окна. Обучение калибровки использует объединённые признаки обоих окон на внутренней калибровке. Порог определяется до оценки. MAT и число вызовов сканера совпали во всех вариантах. Пять серий выполнены с чередованием порядка на одной RTX 4090. Сквозное время окна вокруг найденного участка превысило время окна из середины в четырёх сериях. Медиана парной разницы составила +0,575 с. Сквозная медиана базы в этой серии отличается от 8,034 с в исходной квитанции релиза. Для сравнения вариантов используем замеры из одной серии. Внутренний review содержал 4 294 функции и по 450 дополнительных окон. F1 vulnerability составил 0,956997 у базы и окна из середины и 0,956648 у окна вокруг найденного участка. Состав окон совпал по позиции начала для 40 публичных и 4 внутренних функций. Все 61 310 решений замороженной базы совпали с сохранённым публичным прогнозом релиза.
