# NLBSE 2027 · совместное обучение на исторических компонентах

Продолжили обучение компактного энкодера над тремя выходами, общей `vulnerability`, исторической `W` и объединённой меткой Big‑Vul/Devign. Четыре модели использовали один вход, одинаковый объём обучения и дистилляцию выходов, которыми пользуется текущая маршрутизация. В каждой паре контроль обучался только на `vulnerability`. В двух вариантах обучалась только дополнительная голова, в двух обновлялись также последние два локальных блока и слой глобального внимания. У замороженных вариантов исходные логиты первого прохода совпали побитово. [Параметры A](training/test_a/fit.json) · [Параметры B](training/test_b/fit.json) · [Внутренний прогон](training/official/fit.json)

На A и B обучение и проверка разделены по проектам и файлам. Во внутреннем разбиении official разделены строки и удалены точные дубликаты, но 20 429 из 21 486 строк разработки принадлежат файлам, уже встречавшимся в исходном fit. Дополнительная проверка ограничена 213 строками калибровки и 200 строками review с известными и новыми путями. Из 864 настроек отбора две прошли числовой фильтр. Обе обучены только на `vulnerability`. Дополнительные метки не улучшили F1 на отложенных проектах по условиям отбора. [Таблица](comparison/comparison.csv) · [Проверка новых файлов](comparison/selection.json)

У 43 305 официальных обучающих функций исходная Big‑Vul/Devign-разметка явно присутствует. Ещё 168 809 строк сопоставлены с архивом, где этих меток для строки нет. Линейная голова, обученная только при явной разметке, лучше ранжирует этот исторический исход на обоих отложенных наборах. Интервалы получены парным бутстрэпом по файлам, 1 000 повторов. Результат относится к внешней метке, оцениваемой на строках, где она известна.

| Группа | AP с отсутствующими метками как отрицательными | AP с маской явной разметки | 95% интервал разницы |
|---|---:|---:|---:|
| A | 0,13251 | 0,17369 | +0,03572 … +0,04729 |
| B | 0,11680 | 0,12682 | +0,00047 … +0,02163 |

Ни одна из 432 поправок общей метки по сигналу этой головы не прошла отбор. [Покрытие](support/receipt.json) · [Отбор](probe_comparison/selection.json) · [Бутстрэп и сверка](audit.json)

Замороженный контроль с дополнительной головой снял по одному FP при неизменном TP на внутренней калибровке и review. На публичных 30 655 функциях замороженный порог изменил confusion matrix `vulnerability` с 9 559 TP и 423 FP до 9 555 TP и 414 FP. F1 `vulnerability` вырос с 0,954278 до 0,954498. MAT и 7 279 запросов сканера совпали. При расчёте по медианным затратам пяти пар с чередованием порядка контроль с головой дал 0,964935 против 0,964790, выиграв **3 из 5** пар при заранее установленном требовании 4. Кандидат сохраняется как результат исследования. Рекомендованный архив раунда 38 по-прежнему имеет подтверждённые 0,964721. ## Воспроизведение на Banana

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 TOKENIZERS_PARALLELISM=true RAYON_NUM_THREADS=4 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
py=.venv/bin/python
r=nlbse/round51
$py "$r/support51.py"
for part in test_a test_b; do
  $py nlbse/cuda_launch.py "$r/train51_project.py" "$part"
done
$py nlbse/cuda_launch.py "$r/train51.py" official
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$r/eval51.py" "$part"
  $py nlbse/cuda_launch.py "$r/probe51.py" "$part"
done
$py "$r/select51.py"
$py "$r/pick_probe51.py"
$py nlbse/cuda_launch.py "$r/live51.py"
$py "$r/audit51.py"
```
