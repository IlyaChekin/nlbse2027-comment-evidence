# NLBSE 2027 · условная голова и ранняя остановка сканера

## Контроль на отложенных проектах

Во всех строках ниже сравниваются дополнительные истинно положительные решения при прежнем числе ложных срабатываний **отдельно в каждом проекте**. Группа A состоит из Chromium, QEMU и FFmpeg. Группа B содержит Firefox и ещё шесть семейств. В каждой ротации энкодер обучался на её fit, калибровочная голова и пороги видели отдельные файлы разработки. Ротации и число ложных срабатываний контроля одинаковы для всех вариантов. [Разбиения](../round19/partition.json) · [Все метрики и замороженные пороги](comparison.csv)

| Вариант | Группа A, ΔTP | Группа B, ΔTP |
|---|---:|---:|
| Продолжение условной модели, BCE | −34 | +5 |
| Вес по трудности примеров без срабатывания правила | −31 | 0 |
| Асимметричный вес трудных отрицательных | −32 | +2 |
| Линейная поправка к голове, энкодер заморожен | −4 | −1 |
| Линейная поправка с весом по трудности, энкодер заморожен | −12 | 0 |
| Признаки того, какие конкретно правила сработали | −50 | −11 |
| Дополнительная проверка после удаления переноса внутри скобок | **+11** | **+10** |

Полное дообучение модели увеличило FP при замороженном пороге на A на 1 203–1 314. Самостоятельное ранжирование примеров без правил, AP, снизилось с 0,14276 до 0,12350–0,12516 на A и выросло с 0,27584 до 0,28310–0,29068 на B. Изменение весов в одной голове сделало отклонения меньше. Порог с метками проекта нужен только в диагностическом столбце и не используется при инференсе. [Группа A](test_a/evaluation.json) · [Группа B](test_b/evaluation.json)

Дополнительная проверка заменяет перенос пробелом внутри скобок вне распознанных комментариев и литералов. В диагностике добавилось 248 TP и 649 FP на A и 53 TP и 84 FP на B до отбора и калибровки. Калиброванный повторный скан ограничивается функциями, у которых первое точное сканирование не нашло срабатываний. В данных разработки двух ротаций весь новый сигнал пришёл из одной проверки. На официальных внутренних файлах повторная проверка сохранила 1 337 TP при 100 FP. Учитывая фактическую дополнительную стоимость, выбор по калибровке сохранил контроль. На отдельном внутреннем fold лучший по стоимости вариант снял три FP при тех же TP. Его результат относится к этому fold. [Варианты форматирования](reflow/full/results.json) · [Выбор на внутренних файлах](layout_official/policy.json)

## Сокращение стоимости без потери качества

Локальный балл вырос с **0,961954** до **0,962113**. Медиана сканирования снизилась с **3,99 до 3,06 с**, сквозное время с **7,91 до 6,92 с**. Учитываемое формулой время 5,15 с и 14 773 расчётных GFLOPs. [Пять парных замеров](union_public/results.json)

Условная модель различает срабатывание правила, отрицательный ответ всех правил и неопределённый результат. После первого срабатывания остальные проверки уже не могут изменить этот ответ. Для порядка проверок использованы оценки времени отдельных правил и число новых срабатываний на официальном fit. Отрицательный и неизвестный исход по-прежнему используют все двадцать правил. [Порядок и источники](union_scanner.json)

Короткий путь воспроизвёл все **214 586** результатов полного скана на обучающем наборе. В пяти чередующихся публичных прогонах проверены 7 279 точных ответов на запросы и все 61 310 бинарных решений. F1 vulnerability **0,94569**, F1 MAT **0,93474**, средний F1 **0,94021**. [Проверка совпадений](union_verification.json) · [Замеры и прогнозы](union_public/results.json)

## Воспроизведение

Рабочая директория Banana содержит данные, веса и Node.js. Обзор агрегатов можно пересчитать из сохранённых локально файлов стандартным Python.

```bash
r=nlbse/round22
py=.venv/bin/python
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
for part in test_a test_b; do
  $py nlbse/cuda_launch.py "$r/train.py" "$part"
  $py nlbse/cuda_launch.py "$r/project_eval.py" "$part"
  $py nlbse/cuda_launch.py "$r/frozen_head.py" "$part" fit
  $py nlbse/cuda_launch.py "$r/frozen_head.py" "$part" collect
done
$py "$r/individual_rules.py"
$py "$r/reflow.py" --pilot
$py "$r/reflow.py"
$py "$r/reflow_eval.py"
$py nlbse/cuda_launch.py "$r/layout_official.py" tune
$py "$r/union_scanner.py" build
$py "$r/union_scanner.py" verify
$py nlbse/cuda_launch.py "$r/union_public.py"
python3 "$r/summarize.py"
$py "$r/build_release.py"
$py nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round22_union_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$r/release_verification" \
  --entry "$r/predict_union.py" --cuda-launch
```
