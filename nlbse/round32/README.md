## Что изменилось

Сканер раньше возвращал только факт срабатывания. Теперь при том же раннем выходе доступны позиция первого правила в порядке проверок и число его совпадений. На всех 7 279 публичных вызовах трёхзначный результат совпал с контрольным. Два правила составили 267 из 274 исходных FP среди функций с положительным ответом. Публичные метки использовали для описания ошибок. Пороги и параметры получены на внутренних файлах. [Сверка сканера](first_hit_public.json)

На fit оцениваем поправку к логарифмическому отступу от конкурсного порога. Коэффициенты зависят от первого правила. В модель входят свободный член, наклон по исходному отступу и коэффициент при `log1p` числа совпадений. Штраф стягивает коэффициенты редких правил к общей оценке. Поправка включается только при положительном ответе и абсолютном отступе меньше 1,8. Оценивание использует уже вычисленные вероятности и результаты сканера. [Замороженные параметры](calibrated_rules/official/models.joblib) · [Отбор без публичных меток](selection.json)

| Метод | Убрано FP при прежнем TP, A / B | Сверх перекалиброванного контроля, A / B | Калибровка и review |
|---|---:|---:|---|
| Лучшая простая поправка на компактных оценках | 0 / 3 | 0 / 1 | +2 FP на калибровке, +3 FP на review |
| Согласие с прогнозом конкретного правила | 0 / 3 | 0 / 1 | −2 FP на калибровке, −8 FP и −3 TP на review |
| Ранжирование по UniXcoder, окно 1,8 | 5 / 3 | 5 / 1 | +17 FP на калибровке, +18 FP и −1 TP на review |
| Калибровка по правилу и числу совпадений | 0 / 3 | 0 / 1 | −3 FP на калибровке, −6 FP и −2 TP на review |

При прежнем FP каждого проекта выбранная поправка вернула **6 TP** на A и **4 TP** на B. В диагностике при прежнем TP она сохраняет число FP на A и убирает один дополнительный FP на B относительно перекалиброванного контроля. С этим критерием допускаем равенство на одной группе, если другая улучшилась, recall вырос при прежнем FP на обеих, а F1 вырос на внутренних калибровке и review. Ни одна комбинация из 618 не дала строго положительного снижения FP при прежнем TP на обеих группах относительно перекалиброванного контроля и одновременно не подняла внутренний F1. [Сравнения](comparison.csv)

Для эксперимента с согласием с правилом восстановлены 55 825, 59 441 и 63 703 внефайловых оценок компактной модели на положительном ответе. В сравнении UniXcoder использованы 1 536 замороженных компонент, головы обучены на разных файлах с исключением известных копий. Архив этих признаков хранится на Banana. ## Воспроизведение

Из корня экспериментов на Banana.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
py=.venv/bin/python
round=nlbse/round32
$py "$round/first_hit32.py" build
$py "$round/first_hit32.py" verify
$py nlbse/cuda_launch.py "$round/collect_dense.py"
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$round/collect_aux.py" "$part"
  $py nlbse/cuda_launch.py "$round/eval32.py" "$part"
  $py nlbse/cuda_launch.py "$round/eval32.py" "$part" --agreement
  $py nlbse/cuda_launch.py "$round/dense_rank.py" "$part"
  $py nlbse/cuda_launch.py "$round/subgroups32.py" "$part"
done
python3 "$round/summarize32.py"
$py nlbse/cuda_launch.py "$round/live32.py"
$py "$round/audit32.py"
$py "$round/build32.py"
$py nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round32_rule_calibration_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$round/release_verification" \
  --entry nlbse/round25/predict_sections.py --cuda-launch
python3 "$round/release_summary.py"
```

До 0,97 остаётся **0,005625**. При прежней стоимости и vulnerability для 0,97 потребовались бы 18 дополнительных TP MAT с прежними FP. При прежней стоимости и MAT требуется вернуть 365 пропусков vulnerability с прежними FP либо убрать 387 FP с прежними TP.
