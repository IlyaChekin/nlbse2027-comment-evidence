# NLBSE 2027 · разреженная поправка в группе с отрицательным ответом сканера

Локальный балл на 30 655 публичных функциях **0,962405** против **0,962118** в пяти чередующихся прогонах. С зафиксированными порогами поправка дала **+26 TP и +3 FP**. При прежних **712 FP** она также даёт **+26 TP**. Сравнение при равном FP использует метки только для диагностики и сохраняет все решения вне группы поправки. [Замеры и хеши прогнозов](public/results.json) · [Проверка по файлам](public/audit.json)

## Раздельное обучение и калибровка

Для каждой ротации и официального fit обучены два разреженных логистических эксперта для случаев со срабатыванием WeakSATD и без него. Сравниваем униграммы и биграммы токенов с добавлением символьных фрагментов имён. Для калибровки вероятности собираются прогнозы из четырёх групп, разделённых по исходным файлам. Токенные копии файла оценки исключаются из fit каждой группы. Смесь и рабочий порог выбираются на отдельных файлах разработки. [Манифест признаков](features/manifest.json) · [Обучение A](test_a/fit.json) · [Обучение B](test_b/fit.json) · [Официальное обучение](official/fit.json)

Общее смешивание оценок снизило TP на A даже у лучшего диагностического варианта. В этом варианте улучшение ранжирования функций без правил сопровождалось потерей в группе со срабатыванием. Поэтому отдельно сравнили поправки, действующие только внутри одной группы. В рабочем варианте сканер сначала должен вернуть известный отрицательный ответ. Существующий порог применяется в остальных случаях. [Все варианты](experiments.csv)

| Вариант | Дополнительные TP на A | Дополнительные TP на B |
|---|---:|---:|
| Токенный эксперт при отрицательном ответе, полное смешивание | +69 | +13 |
| Токенный эксперт при отрицательном ответе, смесь 0,5 | **+56** | **+9** |

В каждой группе число FP зафиксировано отдельно для каждого проекта. Официальная внутренняя калибровка выбрала смесь 0,5. Она дала +3 TP при 100 FP, обработала 645 функций и заняла 0,066 с дополнительного времени. На отдельной внутренней проверке фиксированный порог дал +5 TP и +7 FP. Использование идентификатора первого сработавшего правила дало +3 и +4 TP при той же проектной процедуре сравнения, а на внутренней калибровке сохранило исходные TP. [Выбор и замеры](official/tuned/policy.json) · [Идентичность первого правила](first_hit/official/policy.json)

## Измеренный публичный результат

| Метрика | Контроль | Разреженная поправка |
|---|---:|---:|
| Vulnerability F1 | 0,94569 | 0,94689 |
| MAT F1 | 0,93474 | 0,93474 |
| Средний F1 | 0,94021 | 0,94081 |
| Сквозная медиана, с | 6,79 | 7,38 |
| Время в формуле, с | 5,12 | 5,49 |
| Локальный балл | 0,962118 | **0,962405** |

Дополнительный разреженный этап обрабатывает 4 476 функций. Его медиана **0,464 с**, вычисления разреженных произведений добавляют приблизительно 0,0024 GFLOPs. Изменения vulnerability за пределами этой группы отсутствуют. Парный 95%-й интервал по файлам для разницы vulnerability F1 составляет от +0,026 до +0,217 процентного пункта. Проверка новой чистой распаковки воспроизвела все **61 310** решений. [Парный замер](public/results.json) · [Сверка архива](release_verification/receipt.json)

В группе с точным отрицательным ответом остаются 230 пропусков и 331 ложное срабатывание. Идеальное исправление этой группы при сохранении остальных решений и нынешней стоимости дало бы 0,97060. Даже при идеальном снятии всех 331 FP потребовалось бы вернуть 191 из 230 пропусков. Это арифметический сценарий для определения масштаба задачи. [Расчёт](target_gap.json)

## Воспроизведение

Полная разреженная матрица хранится на Banana. Остальные артефакты и прогнозы лежат рядом с отчётом. Запуск из корня рабочей директории с официальным набором данных, CUDA и Node.js.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
p=.venv/bin/python
r=nlbse/round24
$p "$r/crossfit_sparse.py" cache
for part in test_a test_b; do
  $p "$r/crossfit_sparse.py" "$part"
  $p "$r/veto.py" "$part"
  $p "$r/conditioned.py" "$part"
done
$p "$r/crossfit_sparse.py" official
$p "$r/first_hit.py"
$p nlbse/cuda_launch.py "$r/first_hit_internal.py"
$p nlbse/cuda_launch.py "$r/internal_sparse.py"
$p nlbse/cuda_launch.py "$r/public_sparse.py"
$p "$r/audit.py"
python3 "$r/summarize.py"
$p "$r/build_release.py"
$p nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round24_sparse_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$r/release_verification" \
  --entry "$r/predict_sparse.py" --cuda-launch
```
