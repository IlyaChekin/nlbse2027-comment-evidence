## Как обучали и отбирали

Сравнивались пропуски с двумя отрицательными оценками и ложные срабатывания после фактического положительного ответа. Две поправки обучались на прогнозах для файлов вне обучения их исходного энкодера. При сравнении комбинации был один общий порог на объединении обеих областей. Метки каждого отложенного проекта использовались для диагностических сравнений при равном FP или TP. Порог для реального применения вычислен на внутренних данных и заморожен перед публичным прогоном.

Компактная поправка использует предсказания правил, номер первого срабатывания, число его совпадений и прежнюю оценку. В обучении сравнили одинаковые признаки без парной потери и с ней. В официальной ротации на положительной ветви 42 750 внефайловых строк и 3 870 пар. В парах верно принятый пример и ложное срабатывание из того же файла сопоставлены по длине и базовым оценкам. Голова добавляет линейный остаток к существующему отступу. Дополнительный вызов энкодера для неё не нужен. [Таблица отбора](comparison.csv) · [Замороженный выбор](selection.json)

|---|---:|---:|---:|---:|
| Обычная линейная голова | +17 / +6 | 0 / 0 | 0 / −2 | −1 / −3 |
| Попарная линейная голова | +15 / +6 | 0 / 2 | 0 / −2 | −1 / −4 |
| Попарная голова с оценкой учителя | +18 / +6 | 0 / 3 | 0 / −2 | −1 / −4 |

Для выбранной попарной головы прирост при равном FP сверх отдельного изменения порога равен −2 и 0 TP. При прежнем TP сверх порогового контроля снято 0 и 1 FP. Пороговый и попарный варианты по-разному распределяют ошибки на проектах. В отборе 26 из 738 настроек прошли проверки, все принадлежали положительной ветви. Ни отрицательная ветвь отдельно, ни комбинация ветвей не прошли весь протокол. [Отчёты A](comparison/test_a/results.json) · [B](comparison/test_b/results.json) · [Внутренние](comparison/official/results.json)

Новый учитель использует замороженные векторы UniXcoder. Для каждого из четырёх сгибов обучены две головы на одинаковых примерах, одна с попарной потерей. Свой файл и его известные копии исключены из обучения. Внутри пар из положительной ветви текущий ранг даёт **89,2% / 87,6% / 83,4%** правильного порядка. Учитель с обычной потерей даёт **80,6% / 79,3% / 75,4%**, с попарной **79,9% / 79,2% / 74,7%**. Когда оценка учителя используется как дополнительный вход в линейной поправке, внутренняя калибровка и review повторяют качество дешёвой пары. Старый UniXcoder расширен на все отложенные строки с двумя отрицательными оценками и проверен отдельно. Полные результаты всех правил добавляли в тех же экспериментах как исследовательский признак. Из 144 дополнительных конфигураций ни одна не улучшила обе группы и внутренние данные относительно сравнимого контроля по первому срабатыванию. Дополнительный проход сканера в релизе отсутствует. ## Резерв качества

После точного положительного ответа остаются **229 FP**, из них **216** приходятся на одно первое правило. **143** из этих FP сохраняют отступ не меньше 1,8, то есть обычное уточнение ближайших к порогу не затрагивает значительную часть этой группы. После отрицательного ответа остаются **339 FN**. Среди 135 пропусков с двумя отрицательными оценками 102 лежат ниже отступа −1,8. Совершенная коррекция только наблюдаемой отрицательной ветви при текущей стоимости дала бы расчётные **0,971437**. При прежних решениях MAT и стоимости для 0,97 нужны **343 TP** при прежнем FP или устранение **363 FP** при прежнем TP. [Аудит когорт](census.json) · [Сверенная метрика](release_summary.json)

## Воспроизведение

Команды из корня исследования на Banana. Веса промежуточных учителей и замороженные датасеты сохранены рядом с результатами. Повторный замер сохраняет новое время, поэтому исторический архив и его квитанцию лучше сверять отдельно.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
py=.venv/bin/python
path=nlbse/round38
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$path/teacher38.py" "$part"
  $py nlbse/cuda_launch.py "$path/negative38.py" "$part"
  $py "$path/rank38.py" "$part"
  $py "$path/scan38.py" "$part"
done
$py "$path/select38.py"
$py "$path/select_scan38.py"
$py nlbse/cuda_launch.py "$path/live38.py" primary
$py "$path/audit38.py"
$py "$path/build38.py"
$py nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round38_paired_rule_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$path/release_verification" \
  --entry nlbse/round25/predict_sections.py --cuda-launch
$py "$path/census38.py"
$py "$path/release_summary.py"
```
