# NLBSE 2027 · можно ли восстановить MAT по поведению функции

Точный исходный аудит связывает все 61 публичный пропуск с тегами в предшествующих комментариях, отсутствующих в конкурсном `Function`. На двух группах проектов это подтверждено у 99 из 100 пропусков. В конкурсном тексте 75 из 100 пропусков вообще не имеют лексического комментария. В новом опыте использовали только `Function`, который указан как вход в спецификации задачи. [Аудит происхождения](../round48/README.md) · [Спецификация данных](https://github.com/nlbse2027/code-comment-classification#dataset)

Проверили, указывает ли на долг расхождение между действием в имени функции и наблюдаемым поведением тела. Например, оценили случаи, когда название обещает изменение состояния, а тело состоит из возврата константы, либо не использует аргументы. Остальные признаки описывают вызовы, управление, присваивания и явные сигналы заглушки. Частоты поведения оцениваются по семействам имён без использования меток. Для обучающей строки частоты считаются без её группы файлов. При редких именах используются более широкие группы глаголов и глобальные частоты. Деревья обучались на 151 747 функциях, где канонический разбор предсказывал отрицательный MAT, включая 302 пропуска. Калибровка и обе группы проектов не пересекаются с fit по файлам. Точных копий последовательности кодовых токенов между fit и проверочными частями не обнаружено. [Признаки и фиксированные пороги](contract/policy.json)

Замороженный порог из development вернул 0 пропусков у всех пяти вариантов. У прежнего признака расположения одно диагностическое исправление требует порога с размеченных строк Android. В новом варианте с частотами первый возврат требует хотя бы 27 FP на A и 37 на B даже при диагностическом пороге по отдельному проекту. Остаточная AP этого варианта 0,00490 на A и 0,00406 на B. Эти значения выше контроля размеров и ниже контроля расположения комментария на обеих группах. [Метрики](contract/comparison.csv) · [Порог первого возврата](contract/results.json)

Из 100 пропусков у 99 есть хотя бы один учтённый признак тела из вызовов, присваиваний, управляющих конструкций и делегирования. Явный лексический сигнал заглушки есть у одного пропуска и 576 отрицательных функций. Связка «имя обещает изменение состояния, тело без наблюдаемого действия» не встретилась ни в одном пропуске и присутствует у 308 отрицательных функций. Проверка не нашла у пропусков побайтно одинаковый отрицательный `Function` внутри каждой выборки, включая публичную. Отсутствие тега объясняет ошибки текущего разбора. Опыт не даёт верхней границы для всех предсказателей по коду. [Прогнозы и независимая сверка](audit.json)

Дополнительный признак искал упоминание имени функции в теговых комментариях к другим функциям из fit. Каждый обучающий файл давал не более одного голоса для имени. Имена с упоминаниями в обычных комментариях штрафовались. Проверили шесть вариантов по точным вызовам, идентификаторам и глаголам исправления. Индекс нашёл 212 имён в самой широкой версии. Ни одно из этих имён не сопоставилось с пропусками на A или B. При 0 FP и с замороженными порогами все шесть вариантов вернули 0 на обеих группах. [Метрики поиска упоминаний](references/comparison.csv) · [Покрытие по группам](references/results.json)

Публичный набор использован для сверки происхождения и точных совпадений текста. Новый предсказатель не прошёл отбор на A/B. При прежней `vulnerability`, стоимости и 0 FP прибавка в 16 публичных MAT TP дала бы 0,970015. Подтверждённый локальный балл остаётся **0,964721**, MAT F1 **0,935722**. При текущем среднем F1 даже нулевые время и GFLOPs дали бы только 0,967000. [Текущая сводка](../round38/release_summary.json)
