# NLBSE 2027 · почему пропускается MAT

22 ноября 2026 года. Учёт соседних символов у корня тега вернул **3 из 84** пропусков на одной группе отложенных проектов при тех же **2 ложных срабатываниях**. На второй группе результат **0 из 24** при **0 ложных срабатываний**. На публичной валидации улучшение отсутствует. [Проверенные таблицы](results.csv) · [Публичные сравнения](public_results.csv)

## Что модель видит в тексте

Модель раунда 12 распознаёт MAT по `TODO`, `FIXME`, `XXX` и `HACK` с границами слова в C/C++-комментариях по всему входу. Окно компактного энкодера ограничено, а этот лексический признак получает полный текст. В исходной работе MADE-WIC разметка MAT использует четыре тега в связанных комментариях, включая комментарии перед функцией. В конкурсном наборе модель получает одну колонку `Function`. Установить происхождение каждой отсутствующей подсказки по одной этой колонке невозможно. [Статья о MADE-WIC](https://arxiv.org/html/2408.05163v1#S2.SS2) · [Конкурсная постановка](https://github.com/nlbse2027/code-comment-classification#competition-task)

|---|---:|---:|---:|---:|---:|---:|
| Группа A | 31 098 | 830 | 2 | 84 | 30 | 54 |
| Группа B | 7 899 | 204 | 0 | 24 | 3 | 21 |
| Публичная валидация | 30 655 | 505 | 1 | 62 | 19 | 43 |

В публичных 19 случаях с комментариями сканирование подстроки также не находит ни одного из четырёх корней. В оставшихся 43 строках отсутствуют даже разделители `//` и `/*`. Независимый парсер Tree-sitter нашёл комментарии в тех же 19 строках. Среди 43 случаев есть один тег вне комментария. В старой диагностике эта строка была отдельной категорией, поэтому там 42 случая без комментария и тега. Совпадающих полных текстов с отрицательной меткой для 62 публичных пропусков нет. Один из 62 текстов совпадает с положительной функцией официального fit. [Срезы](audit_test.json) · [Два парсера](coverage.json) · [Проверка совпадений](ambiguity_public.json)

## Проверка признака

Группы проектов зафиксированы по ротации R13. Для обучения новых голов использовано 153 628 функций Linux. Для выбора конфигураций и порогов использовано 21 797 функций из отдельных файлов Linux и tcpdump. Группа A включает Chromium, QEMU и FFmpeg. Группа B включает Firefox, Android, PHP, ImageMagick, radare2, krb5 и file. Ни одна из групп не участвует в обучении или калибровке этой проверки. Совпадающие токенные отпечатки между разделами отфильтрованы в R13. Разбиение относится к этой серии моделей. Проекты участвовали в разных ролях в более ранних прогонах. [Разбиение](../round13/partition.json) · [Данные](../data/manifest.json)

Признак распознаёт корень тега внутри комментария и кодирует соседние символы, регистр, положение в комментарии и лексическую область. Он отличает тег с буквенным суффиксом от произвольного совпадения внутри строки либо идентификатора. В сравнении участвовали простое ослабление границ слова, символьные n-граммы комментария, кодовые n-граммы, обучение на коде с удалённым комментарием и сходство с обучающими функциями по редким цепочкам токенов. В публичных экспериментах менялась только голова MAT. [Код признака](mat.py) · [Поиск похожих функций](prototype.py)

При замороженном пороге признаки тега вернули по одному пропуску на Chromium, QEMU и FFmpeg, с прежним числом FP на каждом проекте. MAT F1 группы A вырос с 0,94550 до 0,94750. Парный 95%-й бутстрэп-интервал по файлам для ΔF1 составляет от 0 до +0,47 п.п. Во всех трёх случаях виден корень `HACK` с буквенным суффиксом. Маскирование корня снимает все три срабатывания. Восстановление границы слова возвращает все три штатному детектору. Это проверяет механизм найденного эффекта. Диагностические пороги при одинаковом числе FP вычислены отдельно на тестовых метках. ## Публичный результат и цель 0,97

В паре на 30 655 функциях признак с порогом разработки воспроизвёл прежние MAT-решения и добавил 0,44 с сканирования. Медиана сквозного времени на RTX 4090 выросла с 4,06 до 4,36 с, локальный балл снизился с 0,95670 до 0,95662. Переобучение признака на официальном fit с калибровкой на внутренних строках дало три дополнительных FP при замороженном пороге и ни одного исправления при диагностическом бюджете в один FP. В обоих прогонах двоичные решения vulnerability совпали с архивом раунда 12. [Голова с проектной калибровкой](public/project/marker_geometry/analysis.json) · [Голова с официальной калибровкой](public/official/marker_geometry/analysis.json)

При неизменной vulnerability, одном MAT FP и прежней вычислительной стоимости до 0,97 нужно исправить 41 из 62 пропусков MAT. Даже идеальное исправление всех 19 пропусков с видимым комментарием даёт около 0,9630. В этом сценарии для 0,97 потребуется исправить ещё 22 случая без распознанного комментария. Для подачи остаётся проверенный `selective` с локальным баллом 0,95675. [Арифметические границы](limits.json) · [Проверенный пакет](../submission/NLBSE2027_round12_tool.zip)
