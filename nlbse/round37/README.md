# NLBSE 2027 · раздельные представления объявления и тела

Состояния токенов берутся из первого прохода компактного энкодера. Для каждого участка считаем среднее по токенам, сохраняем общий максимум и подаём эти два вектора в прежние линейные головы. Поправка использует разность региональной и общей оценки. Для обучения каждая строка извлекается чекпойнтом, у которого её файл и известные копии отсутствовали в обучении. На development и отложенных проектах применяются штатные чекпойнты соответствующей ротации. [Манифест A](views/test_a/receipt.json) · [Манифест B](views/test_b/receipt.json) · [Внутренняя ротация](views/official/receipt.json)

В каждой ротации сравнили 485 конфигураций. Варианты включали прежние оценки, все 23 штатных выхода, две половины последовательности, объявление, тело и границу через 48 токенов после начала тела. Границу объявления определяли по первой открывающей фигурной скобке вне строк и комментариев. Контроль деления пополам сохраняет те же слои и размер признака. Дополнительный вариант разделяет влияние региональных признаков по знакам оценки до и после сканирования. Маршрут, пороги MAT и все решения за пределами экспериментальной полосы сохраняются. При одинаковых ширине и доле смешивания деление пополам получило столько же TP, сколько версия со всеми штатными выходами, при FP каждой отложенной группы. Настоящая граница объявления добавила **+1 и 0 TP** сверх признака штатных выходов в сопоставимой конфигурации. На пилоте обнаружилась ошибка сопоставления индекса токена со смещением, когда токенизатор возвращал нулевой интервал внутри последовательности. Исправленная версия использует исходный индекс токена в таблице смещений. Обе проектные группы и внутренняя ротация полностью пересчитаны до заморозки публичных вариантов. Пилотные файлы сохранены на Banana в `boundary_pilot/`.

## Публичные измерения

Все измерения выполнены на 30 655 функциях и RTX 4090. Каждый вариант сравнивался с раундом 34 в пяти парных прогонах с чередованием порядка. Для контроля полное совпадение 61 310 бинарных решений проверялось при каждом запуске. В каждом варианте сохранены 7 279 запросов к сканеру, 1 990 проходов по канонизированной версии и вся голова MAT. **Выбран отложенный вариант.** Он сохраняет состояния первого прохода, отбирает 277 строк после точного сканирования и готовит разметку границ только для этих строк. Он повторяет все бинарные решения исходного варианта с объявлением и телом. Добавка **0,086 аналитических GFLOP** против **26,06** в исходном варианте. Пиковый объём удержанных тензоров **7,05 ГБ**. При заполнении буфера представления для очередного пакета вычисляются сразу. В тесте с принудительно нулевой вместимостью совпали все 61 310 решений. Для повтора проверки памяти в отдельной распакованной копии установите `self.limit = 0` в методе `ScopedStates.start` и сравните выходные биты с `examples/public_expected.csv`.

В новой парной серии локальный балл **0,964573 против 0,964456**, выигрыш во всех пяти парах. F1 vulnerability **0,953630**, MAT **0,935722**, средний **0,944676**. При диагностическом прежнем FP улучшения recall на публичном наборе нет. Парный 95%-й bootstrap-интервал изменения F1 vulnerability по файлам от −0,032 до +0,114 п.п. В итоговом ZIP используется тот же единственный чекпойнт. Из чистой распаковки воспроизведены все 61 310 решений. ## Резерв до 0,97

На подписанных данных раунда 34 из отрицательных ответов сканера **222** пропуска следуют за положительной оценкой до запроса. Ещё **135** остаются отрицательными на обеих ветвях. В той же группе **93** ложноположительных решения. Даже идеальное исправление всех ошибок в полосе 0,4 даёт только **0,966260** при прежней стоимости. При восстановлении 250 из 357 пропусков потребовалось бы устранить 116 ложных срабатываний. Значит, в этом сценарии нужен выигрыш и на других ветвях, где остаётся 247 FP после положительного ответа и 90 без наблюдаемого ответа.

Для продолжения сформированы новые внефайловые пары из одного файла. В группе пропусков с двумя отрицательными оценками исходный UniXcoder повысил долю верного порядка пар с **58,2% до 60,4%** на A, с **60,7% до 66,4%** на B и с **63,5% до 64,2%** во внутренней ротации. Для ложных срабатываний после положительного ответа получены **5 822**, **4 676** и **3 870** пар. Старый учитель этот срез не покрывает. Каждая пара хранит маски совпадений с обучающими файлами. Расчёты по публичным меткам использовались для диагностики, а пары собраны из официального train. [Срезы и пределы](scope.json) · [Состав и сравнение пар](matched/results.json)

## Воспроизведение

Из корня экспериментов на Banana, где лежат закреплённые parquet и веса внефайловых энкодеров. При повторе исторических замеров используйте отдельный каталог для новых файлов профилирования.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
py=.venv/bin/python
path=nlbse/round37
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$path/section37.py" "$part"
  $py "$path/eval37.py" "$part"
done
$py "$path/select37.py"
for arm in primary native semantic; do
  $py nlbse/cuda_launch.py "$path/live37.py" --arm "$arm"
done
for mode in dense gated deferred; do
  $py nlbse/cuda_launch.py "$path/live37.py" --arm semantic --optimized "$mode"
done
$py "$path/audit37.py"
$py "$path/scope37.py"
$py "$path/pairs37.py"
$py "$path/build37.py"
$py nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round37_deferred_sections_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$path/release_verification" \
  --entry nlbse/round25/predict_sections.py --cuda-launch
$py "$path/release_summary.py"
```
