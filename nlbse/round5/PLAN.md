# Выбор дополнительного контекста для CodeT5+

Основной результат — измеримый эффект второго окна на одном замороженном классификаторе. Изменяем выбор фрагмента, условие второго прохода и объединение двух прогнозов по отдельности. Пороги 0,70 и 0,50 и FP16-веса совпадают с предыдущим экспериментом в первичном сравнении. Главный контроль воспроизводит старый сканер и окно 128 токенов.

- Контроль содержания. Вместо пропущенного комментария подаём уже виденный фрагмент или хвост такой же длины на тех же строках. Отдельный полный хвост для всех длинных функций оценивает цену простого расширения.
- Выбор фрагмента. Тестируем 64/128/192 токенов, приоритет начала комментария и признаков вроде TODO, два коротких фрагмента разных комментариев. В одном варианте вставляем фрагмент в первое окно без второго прохода. Ещё один контроль читает до 768 последовательных токенов за проход.
- Выбор строк. При max по MAT второй проход можно пропустить, если первая вероятность уже выше порога. Проверяем ожидаемое совпадение решений. Дополнительный хвост для неопределённых vulnerability-прогнозов оценивается отдельно. Вторая вероятность по vulnerability смешивается с первой только в этом режиме.

Выбираем на прежнем разделении из официального train, сравнивая 18 444 строки. Срез 3 042 используется только для отдельной проверки порогов. Первичная таблица сохраняет неизменные пороги. Сценарии замораживаются до публичного прогона. Публичная разметка уже использовалась для предыдущего результата, поэтому это проверка новых фиксированных политик на известном бенчмарке. Для полного GPU-прогона оставляем старый one-pass и comment128, вариант с пропуском уже положительных MAT и не более двух выбранных кандидатов. Диагностические контроли оцениваются без многократного тайминга.

Фиксируем и качество, и стоимость. Используем расчёт операций по реальным формам батчей, фактическое время трёх прогонов и отдельно время от текста до прогнозов. Сравниваем ошибки на обрезанных и коротких функциях, начало и продолжение комментария. Сохраняем бинарные прогнозы и парные интервалы по проектам и файлам.

После первого внутреннего сравнения добавлен тест бюджета первого окна. Проверяем 256 и 384 токена с исходными порогами. На каждой длине сравниваем одно окно и выборочные окна комментария на 64 и 128 токенов. Из внутреннего сравнения до публичного прогона выбираем лучший двухпроходный вариант по той же расчётной формуле и проверяем всего две конфигурации на публичных строках, с первым окном выбранной длины и с коротким возвратом в комментарий.

Для выбора инструмента сохраняем качество исходного правила на внутреннем сравнении. Среди выбранных политик, которые достигают F1 исходного правила, используем максимальный расчётный балл. Публичный результат проверяет этот заранее заданный выбор. При снижении публичного F1 более чем на 0,1 п.п. возвращаемся к 128 токенам с пропуском уже положительных MAT, если этот пропуск воспроизвёл бинарные решения, иначе к исходному инструменту. Вариант с максимальным F1 и результаты при меньшем первом окне также приводятся для сравнения стоимости.
