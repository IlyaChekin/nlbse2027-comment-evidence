# NLBSE 2027 · поправка к архивной метке W

**Подтверждённый локальный балл 0,964721.** Новые поправки проверены на неизменном разбиении A/B и внутреннем review. Код отбирает решения на внутренних данных, а публичные метки участвуют только в диагностической оценке резерва. Для итогового MAT и измеренной стоимости используется раунд 38. [Сверка](audit.json) · [Проверенный архив](../submission/NLBSE2027_round38_paired_rule_tool.zip)

## Что даёт восстановление W

Однозначное сопоставление публичных строк по проекту, пути и токенам восстановило компоненты разметки у **30 292 из 30 655** функций. Входной файл, предсказания, архив MADE-WIC и кеш ответов сканера закреплены хешами. На **678** строках с фактическим вызовом сканера его ответ отличается от архивного W. Совершенное исправление решений vulnerability внутри этого множества даёт **+146 TP, −221 FP** и расчётный балл **0,970186** при прежней стоимости. Простая подстановка архивного W в этой же когорте даёт **+144 TP, −221 FP** и **0,970155**. Оба расчёта используют недоступную модели исходную разметку. [Исходный архив](https://zenodo.org/records/15126132) · [Когорты](public_audit/results.json) · [Расчёт](audit.json)

При устранении всех 221 FP для 0,97 в этой когорте всё равно нужны 134 из 146 TP. При возврате всех 146 TP нужно убрать 209 из 221 FP. В другой когорте внешних положительных меток Big‑Vul/Devign без W текущая модель пропускает **218 из 377** функций. Совершенное исправление только этой группы даёт **0,968098**. Группы пересекаются на двух строках. Совершенное исправление всего их объединения даёт +364 TP, −221 FP и расчётные **0,973516**. [Расклад ошибок](public_audit/results.json)

## Поправки из конкурсного текста

Для каждого ответа сканера обучены прямой контроль vulnerability и раздельная оценка ошибки W с вкладом Big‑Vul/Devign. Входы содержат исходные оценки, первое срабатывание и число попаданий, геометрию совпадений и структуру функции. Для попарного варианта нашли по **706 и 422** пары в официальной ротации. В каждой совпадают файл, сгиб и первый ответ. Длина и исходный отступ близки. Оценки для обучения получены вне файлов, а точные копии из отложенных данных исключены. [Настройки, прогнозы и хеши](models/official/results.json)

Раздельная линейная оценка с геометрией вернула **+3/+3 TP** при прежних FP каждого отложенного проекта. Однофакторный контроль дал на A ещё 2 TP. На review с замороженным порогом поправка сняла 3 FP и потеряла 1 TP. В прямой проверке W при прежних FP предикторы теряли на обоих отложенных наборах даже с диагностическим подбором порога по меткам проекта. Это подтверждает проблему переноса ранжирования. Из **972** настроек ни одна не прошла полный отбор. Дополнительные **54** политики с раздельными порогами и проверкой согласия голов тоже не прошли отбор. [Сравнения vulnerability](comparison/comparison.csv) · [Пороговые политики](selective/comparison.csv) · [Сверка ранга W](audit.json)

Алгоритм восстановления переносов обучался на парах исходной и конкурсной записи из fit. Он меняет существующие пробелы между токенами. Комментарии, директивы и продолжения строк сохраняются. Перед сканированием сверяется последовательность токенов. При меньшем пороге сперва поменялись пробелы в **930 и 287** функциях A/B, а архивные показатели W остались прежними. На внутреннем review получен **1 TP W при 0 новых FP**, обработаны 396 изменений из 910 исходных запросов. Эти числа относятся к W и не измеряют итоговый конкурсный балл. [Построчная сверка](restored/comparison.csv)

## Стоимость сканирования

Сравнили исходное деление на пакеты и распределение по суммарной длине и числу строк. Использовали те же шесть процессов и две непересекающиеся выборки по 7 500 функций. На каждом запуске совпали код ответа, номер первого правила и счётчик. Новый план выиграл по 2 из 4 измерений на каждой выборке. Медианы парной экономии **0,004 и 0,038 с** при пороге отбора 0,10 с.
