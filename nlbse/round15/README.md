# NLBSE 2027 · прогнозы на файлах вне обучения

Сравнение готовит выборку трудных отрицательных для эксперимента с precision vulnerability. Источник — 153 628 обучающих функций Linux из раунда 13. Пять групп назначены по хешу проекта и файла. Для каждого прогона из обучения исключены файлы отложенной группы и функции с совпадающим токенным отпечатком. Наборы проектов для проверки переноса остаются вне этих прогонов. [Манифест пяти групп](folds.json) · [Исходное разбиение](../round13/partition.json)

Каждый UniXcoder стартует с исходного предобученного checkpoint и учится одну эпоху. Компактный энкодер учится две эпохи и получает оценки UniXcoder, обученного на том же наборе функций. Прогнозы для отбора ошибок берутся только на отложенной группе. Проверка отчёта сверяет хеши оценок, порядок строк, обе метки и число общих ложных срабатываний. Для первого просмотра фиксированы пороги обеих вероятностей 0,80, 0,90 и 0,95. Изменение модели и сравнение при равном FP выполняются после сбора пяти групп.

Первая группа проверена на 30 482 функциях. При обеих вероятностях выше 0,90 получено 110 общих ложных срабатываний из 103 файлов. При порогах 0,80 и 0,95 получены 225 и 57. Проверенные результаты каждой группы сохраняются в `fold_N/audit.json` и `fold_N/out_of_fold.csv`. [Проверка первой группы](fold_0/audit.json)

Пять групп покрыли все 153 628 обучающих функций. При обеих вероятностях выше 0,90 получено 565 общих ложных срабатываний, по 102–124 в каждой группе. Если обе вероятности ниже 0,05, зафиксировано 226 общих пропусков. На контроль, дообучение и разреженную голову передаётся один и тот же артефакт с прогнозами вне обучения. [Манифест оценок](mining/manifest.json)

## Выборочный запрос к учителю

Отдельный эксперимент использует согласованные прогнозы раунда 13. Регрессор на отдельных файлах Linux предсказывает, насколько смешивание прогнозов компактной модели и UniXcoder снизит логарифмическую потерю. Вход регрессора состоит из логита компактной модели, длины и простых счётчиков текста. Логит UniXcoder используется для обучения регрессора и при проверке уже выбранных функций. ## Разрыв до 0,97

На публичном наборе у текущего решения 643 ложных срабатывания vulnerability, из них 91 при обеих вероятностях выше 0,90 у компактной модели и UniXcoder. Идеальное устранение всех 643 FP без потери правильных срабатываний подняло бы локальный балл с 0,95675 до 0,96602 при прежних MAT и стоимости. Для 0,97 пришлось бы вернуть ещё 249 пропусков vulnerability. Идеальный выбор правильного бинарного ответа среди десяти фиксированных архивных вариантов при прежней голове MAT дал бы 0,97432, если сохранить прежнюю стоимость. Этот расчёт использует эталонные метки и показывает, какую часть разрыва покрывают разные модели. [Сценарии и использованные архивы](sensitivity.json)

## Продолжение обучения компактной модели

Контроль дистиллирует из UniXcoder с прогнозами вне обучения и даёт +15 TP при 448 FP на отложенных проектах. Повышение веса общих FP даёт +4 TP к исходному энкодеру и −11 к парному контролю. Усиление общих ошибок обоих типов даёт −8 TP к исходному энкодеру. Контекстное усиление учителя, когда его out-of-fold оценка верной метки выше, даёт −3 TP. Разреженная голова с морфологией кода оставила прогнозы без изменений. Все нейросетевые версии получили один исходный checkpoint, одну эпоху и seed 42. [Проверенная таблица](results.csv)

В переносе на официальный fit контроль продолжает обучение со штатным учителем. В двух других вариантах его цели vulnerability смешиваются с вероятностями UniXcoder для 138 268 общих строк, которые этот UniXcoder оценил в своём fit либо вне обучения. Пороги выбираются на внутренних строках из проектных групп или файлов, удержанных от обучения UniXcoder раунда 13.

На 1 266 строках калибровки при 44 FP штатный учитель и подмешивание in-fit UniXcoder дали по +1 TP. Подмешивание out-of-fold дало 0. При равенстве выбран штатный учитель. На независимых 1 223 внутренних строках он дал +3 TP и −2 FP с зафиксированным порогом. На публичном наборе кандидат с одним энкодером дал **0,95720**, средний F1 **0,93076**, 13 898 GFLOPs и медиану **3,70 с** в трёх прогонах. База в той же серии дала 0,95669. С замороженным порогом результат составил +60 TP и +35 FP. Диагностически при ровно 643 FP получено **+15 TP**. Повторный прогон для этого сравнения воспроизвёл все прежние двоичные решения. ## Реальное публичное профилирование

Каскад с маршрутом по ожидаемому снижению потери на 30 655 функциях вызвал учителя 681 раз. При диагностическом бюджете 643 FP найдено ещё 46 положительных примеров. При заранее выбранном пороге эффект составляет +67 TP и +19 FP. Средний F1 вырос с 0,92996 до 0,93132. В трёх прогонах на RTX 4090 медиана сквозного времени выросла с 3,82 до 4,03 с и оценка операций с 13 860 до 22 625 GFLOPs. Локальный балл составил **0,95688** против **0,95671** у базы в той же серии. Простой маршрут по близости к порогу нашёл +114 TP при равном FP, но получил 0,95668 при 39 947 GFLOPs. Каскад требует второй checkpoint. Подтверждённый вариант с одним энкодером оценивается отдельно. [Проверенная публичная таблица](routed_public_table.csv) · [Фактические прогоны](routed_public/results.json)

```bash
$py $r/disagreement.py test
$py $r/intervals.py

bash $r/run_routing.sh

python3 $r/summarize.py
```
