# NLBSE 2027 · признаки пропущенного MAT и перенос от сильного энкодера

## Пропуски MAT на отложенных проектах

Канонический разбор полного `Function` даёт 77 пропусков и 0 ложных срабатываний на A, 23 и 0 на B. A включает Chromium, QEMU и FFmpeg. B включает Firefox, Android, PHP, ImageMagick, radare2, krb5 и file. Группы исключены из обучения. В диагностике с прежним бюджетом порог каждого проекта ограничен его максимальным отрицательным баллом. Замороженный порог выбирается на 21 797 строках development и применяется ко всем проектам.

| Источник признака | A при тех же FP | B при тех же FP | A, замороженный порог | B, замороженный порог |
|---|---:|---:|---:|---:|
| Язык видимого комментария после удаления тега и расположение перед телом | 0 TP | 0 TP | 0 TP, +1 FP | 0 TP, +1 FP |
| Сигнатура и структура тела | 0 TP | 0 TP | 0 TP, 0 FP | 0 TP, 0 FP |

| Аудит исходников, точное совпадение или два якоря | 0 TP | 14 TP | 15 TP, +7 FP | 14 TP, 0 FP |

В первой строке таблицы используется вариант с поправкой на расположение. Полная матрица включает девять оценок из `Function`. Ни одна не вернула пропуск при прежних FP каждого проекта. Классификатор языка обучен на 1 627 различных помеченных комментариях после удаления слова с тегом и 37 563 комментариях без тега. В оценке сигнатуры и тела признаками служат части идентификаторов и строки, с нормализацией чисел и отметками глубины ветвлений. В обучении оценки кода используется повышенный вес 241 пропуска с подтверждённым тегом перед функцией. Новый доступный набор содержит только один пример с видимым предшествующим тегом, который можно удалить для имитации такого пропуска. [Таблица всех текстовых вариантов](mat/text/comparison.csv) · [Рецепт и пороги](mat/text/policy.json)

Для отдельного аудита взяли 73 ранее проверявшихся файла Linux, Chromium и Firefox. Первоначальный список файлов сформирован для разбора пропусков. Скачались 50 закреплённых файлов. Проверены все конкурсные функции из этих файлов на development и A/B. На найденном фрагменте ищем тег внутри или в примыкающем комментарии. Отдельно проверяем начало строки и имя функции в документационном комментарии. Когда точного токенного совпадения нет, проверяем уникальную пару из начального и конечного якорей длиной 12 токенов и сходство последовательности не ниже 0,94. На B все 14 случаев относятся к Firefox. При ослаблении сопоставления на A добавились три FP и ноль TP. Порог из development возвращает 29 TP с 0 FP на 21 797 строках development. Результат на A показывает цену переноса этого порога. Снимки используются для аудита, который читает также `Projectname` и `Filepath`. У конкурсного предсказателя входом служит `Function`. ## Сравнение сильных энкодеров для vulnerability

На одних и тех же отрицательных и ненаблюдаемых исходах сравнили замороженный GraphCodeBERT, сохранённый UniXcoder, их среднее и перенос в имеющееся компактное представление. Учителя размечают внефайловые сгибы. При обучении исключены точные токенные копии функций из оценки. Напрямую смесь учителей вернула +8/+3 TP при прежнем FP каждого проекта. Это +5/+2 сверх контроля из прежних оценок в той же области. Режим с порогом из калибровки обрабатывает пять функций на review и там не меняет TP и FP. Ни одна из 816 проверенных конфигураций не прошла отбор, включая 306 конфигураций переноса. На RTX 4090 один пакетный сбор GraphCodeBERT занял 54,57 с модельного и 59,40 с сквозного времени на 184 318 строках. Это измерение сбора представлений. Новый сквозной конкурсный замер для отклонённых вариантов не проводился. [Таблица](comparison/comparison.csv) · [Отбор](comparison/selection.json) · [Профиль сбора](graph/receipt.json)

## Подтверждённый результат

У раунда 38 локальный балл **0,964721**. При его измеренной стоимости и тех же решениях vulnerability для **0,97** нужно исправить **16 из 61** публичного пропуска MAT при 0 дополнительных FP. Число получено пересчётом формулы. В этом раунде публичные метки для отбора не использовались. Обновлённый черновик на четырёх страницах включает эксперимент в разделе о пропущенном контексте. ## Воспроизведение

Запуск из корня экспериментов на Banana. Крупные массивы `graph/features.npy`, `compact/*/states.npz` и кеш закреплённых исходников хранятся там. Журналы, конфигурации, веса голов, пороги, результаты и построчные прогнозы сохранены локально.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2
py=.venv/bin/python
r=nlbse/round41
$py "$r/mat/text41.py"
$py "$r/mat/source_context41.py"
$py nlbse/cuda_launch.py "$r/collect41.py"
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$r/compact41.py" "$part"
  $py nlbse/cuda_launch.py "$r/heads41.py" "$part"
done
$py "$r/evaluate41.py"
$py "$r/mat/verify41.py"
python3 nlbse/round38/release_summary.py
```
