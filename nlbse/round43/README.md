# NLBSE 2027 · структура вокруг первой отмеченной строки

Проверили, помогает ли синтаксис отличить ошибочные положительные ответы сканера от верных. За основу взят раунд 38. Длины окон, наборы пар и режимы отбора совпадают у структурного и текстовых признаков. Обучение использует функции с положительным ответом, привязанным к строке. В каждом сгибе исключены тот же файл и токенные копии, а при итоговом обучении исключены токенные копии из калибровки и оценки. [Манифест представлений](features/receipt.json) · [Первая серия](comparison/comparison.csv)

Сравнили окно из пяти строк, то же окно с заменой имён идентификаторов и пути от узлов отмеченной строки к их предкам в синтаксическом дереве. Дополнительный контроль берёт синтаксис из середины функции. Синтаксические пути хранят типы узлов, операторов и управляющих конструкций. Они не хранят буквальные имена. C++ используется первым, C заменяет его, когда даёт дерево без ошибки. С набором из 48 636 позиций C выбрали для 438 строк. Осталось 7 251 частично разобранное дерево. При прежнем TP структурная поправка сняла 0 и 3 FP на A и B, сверх самого сильного контроля 0 и 2. Ни одна из 1 008 конфигураций не прошла все критерии отбора. На 1 500 функциях синтаксический проход и его линейная оценка заняли медианные **0,778 с**, текстовый проход **0,148 с**. Замер включает извлечение признаков и применение головы. ## Калибровка уверенных ответов

Отдельно сравнили нелинейную калибровку с монотонностью по отступу базовой модели. Усиленный вариант повышает вес ложных ответов с отступом от 1,8 в обучении. Из 576 конфигураций отбор прошли две полосы одной числовой модели. Выбрали более узкую. Она снимает 0 и 2 FP при прежнем TP, сверх контроля 0 и 1. Калибровка дала +0,0347 п.п. F1 vulnerability, review сохранил прежний F1. [Отбор](conditional/selection.json)

На 30 655 публичных функциях замороженный порог вернул **1 TP и снял 4 FP**. F1 vulnerability вырос с **0,954278** до **0,954520**. Диагностика при прежнем TP даёт **−11 FP**, при прежнем FP **+2 TP**. Медианный конкурсный балл **0,964812 против 0,964795**, три победы из пяти пар. Каждый контроль воспроизвёл 61 310 решений раунда 38. [Сквозной замер](public_conditional/results.json)


Оптимизировали вычисление тех же признаков. Для остальных правил сканер сохраняет решение и счётчик, а геометрию вычисляет только для выбранного правила. Сверили все 7 279 ответов и 2 112 наборов геометрических признаков выбранного правила. Быстрая версия сохранила **61 310** бинарных решений проверяемого кандидата. В шести сбалансированных парах балл **0,964838 против 0,964746**, продолжительность расчёта **6,25 против 6,35 с**, сквозная **7,87 против 8,17 с**. Получено **4 победы из 6** при заранее закреплённом проходном условии 5. Лучший подтверждённый архив остаётся раундом 38 с результатом **0,964721**. ## Воспроизведение

Выполняется из корня экспериментов на Banana. Версии закреплены в `requirements-parser.txt`, контрольные суммы бинарных пакетов в `parser.sha256`. Основная среда экспериментов использует изолированную подпапку парсера.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
py=.venv/bin/python
r=nlbse/round43
sha256sum -c "$r/parser.sha256"
$py -m pip install --no-index --find-links "$r/wheels" --target "$r/deps" -r "$r/requirements-parser.txt"
$py "$r/features43.py"
for part in test_a test_b official; do
  $py "$r/study43.py" "$part"
  $py "$r/conditional43.py" "$part"
done
$py "$r/select43.py"
$py "$r/conditional43.py" select
PYTHONPATH="$r" $py "$r/source_snapshots/live43.py" micro
PYTHONPATH="$r" $py nlbse/cuda_launch.py "$r/source_snapshots/live43.py" conditional
$py nlbse/cuda_launch.py "$r/live43.py" conditional_fast
$py "$r/audit43.py"
```
