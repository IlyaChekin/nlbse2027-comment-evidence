# Дообучение, выбор окна и проверка источника выигрыша

Цель — развить один инструмент CodeT5+ и проверить три гипотезы отдельно. Используются зафиксированные версии NLBSE и существующий FP16 checkpoint. Публичная выборка уже известна из предыдущей работы и служит повторной проверкой после заморозки вариантов. Скрытые данные остаются у организаторов.

1. **Обучение с разным бюджетом.** Одни и те же 40 000 строк официального fit, один проход, одинаковые оптимизатор, зерно и начальный checkpoint. Выборка включает 14 000 длинных по символам функций, чтобы чаще встретить обрезание, и 26 000 остальных, с расслоением по двум меткам. Контроль тренируется на первом окне 384. Во второй ветви на батч назначается 256/384/512 с вероятностями 0,2/0,6/0,2. В обеих ветвях используется целевое окно 64 на строках с пропущенным C-style комментарием, max по MAT и дополнительная потеря на первом проходе. Для всех моделей проверяем одинаковые режимы 384 без дочитывания, 384+64 и 512+128 при прежних порогах. Для сравнения сохраняем и замороженный исходный checkpoint.
2. **Маршрутизация по прогнозируемой пользе.** На том же замороженном энкодере обучаем небольшую голову выбирать между остановкой, чтением окна комментария и повторным чтением до 768 токенов. Истинные исходы трёх действий вычисляются только для train holdout. Группы одинакового текста распределяются между обучением головы, калибровкой бюджета и внутренней проверкой. Выгода учитывает исправления и новые ошибки по обеим меткам. Сравниваем с существующим правилом 384+64 при сопоставимом бюджете, с учётом полного повторного прохода для 768. Выбор коэффициента стоимости фиксируется до публичного прогона. Отдельная меточная политика служит диагностическим сравнением, её шаги используют исходы из разметки.
3. **Удаление содержания при одинаковой форме входа.** На тех же вызовах 128-токенного окна и тех же позициях скрываем токены комментариев или соседнего кода через attention mask. Специальные токены, длина, порядок и границы окон остаются прежними. Проверяем четыре режима: первое окно, полное дополнительное окно, только дополнительный код и только дополнительный комментарий. Повторяем сравнение с новым энкодером, обученным от исходного Salesforce CodeT5+ на 40 000 примерах из других проектов. Chrome и Chromium считаются одной семьёй, Linux и Linux Kernel тоже, PHP и php-src тоже. Семьи Chromium, QEMU и FFmpeg целиком отложены. Удаляем точные дубликаты отложенных функций из supervised fit и калибровки. Это независимость на этапе supervised обучения, предобучение не проверено на совпадения.

Основные метрики — F1 по обеим меткам, средний F1, число дочитываний, формы плотных операций и парные интервалы. Реальный тайминг сравниваем на RTX 4090. Архив предыдущей работы и исходное конкурсное решение сохранены.
