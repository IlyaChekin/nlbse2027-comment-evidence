# NLBSE 2027 · агрегация локальных признаков и длинный контекст

22 ноября 2026 года. В этом раунде проверены сохранение признаков отдельных токенов в компактном энкодере и перераспределение входного окна на функциях, которые превышают 512 токенов. Все сравнения меняют только обработку vulnerability. Правило MAT по полным комментариям сверяется на каждом выходе.

## Голова после глобального внимания

Штатная голова получает среднее и максимум по каждой координате скрытого состояния токенов. Добавлены три остаточные головы. Первая агрегирует четыре проекции по отдельным картам внимания. Вторая сохраняет максимум и среднее шести самых высоких токенных оценок по каждой из восьми проекций. Третья раздельно усредняет проекции в четырёх относительных частях функции. Остаточный вклад касается только оценки vulnerability и стартует с нуля. Сопоставление прежнего и выделенного общего слоя на CPU показало максимальное расхождение логитов 1,2×10⁻⁷, а полный публичный контроль воспроизвёл все 61 310 прежних решений. [Архитектура](heads.py) · [Прежнее разбиение](../round13/partition.json)

Каждый вариант получил ту же дополнительную эпоху, исходные веса с исключёнными проектами, цели UniXcoder, порядок батчей и seed, что и парный контроль. Пороги выбраны на проектах разработки. На 7 899 функциях отложенных проектов сравнение при 448 FP дало следующие изменения TP относительно исходного энкодера.

| Голова | Seed 42 | Seed 101 |
|---|---:|---:|
| Штатное усреднение и максимум | −1 | +1 |
| Внимание по токенам | −1 | −4 |
| Максимум и шесть высоких оценок | −4 | −8 |
| Четыре части функции по отдельности | 0 | 0 |

Отключение головы на том же обученном энкодере показало, что внимание и шесть высоких оценок меняют ранжирование в этом бюджете на 0 TP в обоих seed. Раздельная агрегация четырёх частей даёт 0 и +2 TP относительно отключённой головы. При коэффициенте, заранее выбранном на проектах разработки, общий итог раздельной агрегации составляет 0 и +1 TP относительно исходного энкодера. [Сравнение по seed](project_results.csv) · [Отключение головы и коэффициенты](ablation_results.csv)

Для официального переноса по двум результатам разработки выбрана голова с шестью высокими оценками. На независимой внутренней калибровке из 1 764 строк она дала +0 TP при 41 FP. Штатная голова после такой же эпохи дала +1 TP и прошла в публичный замер. На 30 655 строках её балл 0,957248 против 0,957232 у базы в парной серии. При равном бюджете она теряет 5 TP, с замороженным порогом даёт +38 TP и +42 FP. Средний F1 меняется с 0,930763 до 0,930807. Разница локального балла в 0,000016 здесь сопоставима с разбросом времени разных прогонов. Исходный кандидат с баллом 0,95720 остаётся основной точкой сравнения. [Три прогона](official/results.json) · [Пересчёт из прогнозов](public_results.csv)

## Сжатие токенов перед глобальным вниманием

Штатный энкодер усредняет каждые четыре токена для ключей и значений. Первый вариант учится взвешивать токены внутри каждой группы. Второй отдаёт вниманию и штатное среднее, и взвешенное представление. При 448 FP взвешенное сжатие даёт −3 и −6 TP, удвоенный набор ключей даёт −3 и −10 TP к исходной модели, по двум seed. Парные контроли дают −1 и +1 TP. Удвоенный набор ключей добавил около 7,5% GFLOPs на отложенной группе. [Реализация](memory.py) · [Таблица](memory_results.csv)

## Какие токены сохранять при лимите 512

В публичном наборе 1 739 функций длиннее 512 токенов, максимум 738. У исходного компактного энкодера в этой группе 99 пропусков и 75 ложных срабатываний vulnerability. Идеальное исправление всех этих ошибок подняло бы локальный балл до 0,95983 при прежней стоимости и MAT. [Срез длины](context/audit.json)

На проектной ротации 444 функции из отложенной группы превышают 512 токенов. Верхний бюджет сохраняли тремя способами. Первый даёт 128 токенов началу, 288 середине и 96 концу. Второй распределяет средние 288 токенов по небольшим непрерывным фрагментам. Третий оставляет фрагменты с более редкими токенами в обучении. Четвёртый вариант сохраняет все токены. Протокол подмешивания оценок и пороги зафиксированы на разработке. Столбец с GFLOPs относится только к 444 длинным функциям.

| Вход | Δ TP при 448 FP | Δ TP / Δ FP при замороженном пороге | GFLOPs |
|---|---:|---:|---:|
| Штатный повторный проход | 0 | 0 / 0 | 464,17 |
| Начало, середина и конец, выбран на dev | +7 | +7 / 0 | 464,17 |
| Распределённые фрагменты | +8 | +10 / 0 | 458,46 |
| Фрагменты с редкими токенами | +9 | +7 / −7 | 461,19 |
| Все токены | +9 | +11 / −1 | 562,48 |

Для публичной проверки отдельно калибруется непосредственная замена входа без добавочного прохода. Роль калибровки получают только внутренние файлы из `probe` раунда 13. Выбор сравнивается с простой перекалибровкой исходного окна. [Таблица длинного контекста](context_results.csv) · [Замороженные варианты](context/policy.json)

## Полный контекст в публичном замере

Вариант со всеми токенами выбран на 1 275 внутренних строках при бюджете 22 FP. Он дал +2 TP к исходному ранжированию. На отдельных 898 строках замороженный порог дал +1 TP и +1 FP. В контрольных вариантах менялись только представление входа и порог. Веса, правило MAT и интервалы, в которых запускается канонический вид идентификаторов, взяты из лучшего одиночного энкодера раунда 15.

На полном публичном наборе из 30 655 функций при тех же 678 FP новый энкодер вернул **42 пропуска**. При замороженном пороге получено +64 TP и +22 FP. Средний F1 вырос с 0,93076 до **0,93196**. Парный 95%-й интервал прироста среднего F1 по файлам составляет +0,067…+0,172 п.п. По трём попеременным прогонам на RTX 4090 получено 14 886 GFLOPs, 1,61 с в учтённых участках inference и 4,14 с сквозной медианы. Локальный балл **0,95786** против **0,95723** у базы в той же серии. [Внутренний выбор](context_public/policy.json) · [Публичная таблица](context_public_results.csv)

Собран отдельный архив с одной контрольной точкой. Обычный вход `nlbse/round16/predict.py` в чистой распаковке воспроизвёл все 61 310 бинарных решений на публичном наборе. [Архив](../submission/NLBSE2027_round16_tool.zip) · [Квитанция](release_verification/receipt.json)

## Обучение ранжированию около порога

Два варианта добавляют к обычной дистилляции сравнение пар разной истинной метки. Первый взвешивает пары по близости out-of-fold оценок к рабочему порогу. Второй дополнительно повышает вес пары с похожими оценками. При 448 FP первый даёт +5 и −8 TP относительно исходного энкодера в двух seed. Второй, выбранный на разработке, даёт −1 и −6. Устройство энкодера у этих версий совпадает с контролем. [Ранжирование](margin_rank.py) · [Два seed](ranking_results.csv)
