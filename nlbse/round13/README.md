# NLBSE 2027 · уверенные пропуски коротких функций

21 ноября 2026 года. Проверка на новой группе проектов. Признак связей между употреблениями идентификаторов вернул **0 из 71** уверенного пропуска коротких функций при тех же **448 ложных срабатываниях**. Дополнительное обучение с весами вернуло один правильный ответ по всей выборке при том же бюджете. Это различие укладывается в неопределённость выборки. [Прогнозы и метрики](results.csv)

## Протокол

В предыдущей ротации обе модели давали вероятность vulnerability ниже 0,05 для 1 562 размеченных положительных примеров. Среди них 388 функций были короче либо равны 169 символам. Граница — нижний квартиль длин всех функций предыдущей тестовой ротации. Среди 388 коротких пропусков было 182 тела с несколькими инструкциями, 69 с единственным `return`, 67 с единственным выражением и 34 пустых по синтаксическому разбору тела. [Исходная диагностика](discovery.json)

В этой ротации Mozilla Firefox, Android, PHP, ImageMagick, radare2, krb5 и file отложены от обучения обеих моделей, дистилляции и калибровки. Это новый набор для данной проверки. Firefox, Android и PHP участвовали в разработке предыдущего раунда, остальные входили в прежнее обучение. Chromium, QEMU, FFmpeg и tcpdump составили группу разработки текущей ротации. Универсальный энкодер UniXcoder и компактный энкодер заново обучались на 153 628 функциях Linux из официального `train`. Для отдельных голов выделено 21 642 функции Linux из других файлов. Токенные совпадения между разделами исключили 158 функций из fit и 6 из dev. Разбиение относится к нашему обучению и дистилляции. Предобучение исходных весов выполняли авторы моделей. [Версия данных](../data/manifest.json) · [Разбиение и SHA-256](partition.json)

Тест содержит 7 899 функций, из них 2 854 положительные по vulnerability. В срезе ≤169 символов 1 862 функции и 203 положительных. Совместный порог `<0.05` выделяет 1 602 коротких примера, в том числе 71 пропуск с положительной разметкой. Вес этого среза по проектам распределён неравномерно: Android — 56, Firefox — 9, PHP — 6. [Главный прогон](study/analysis.json)

Новый признак строится по C/C++ AST. Он связывает употребления одного имени внутри функции и учитывает последовательность ролей, включая объявление, параметр, чтение, запись, аргумент вызова и возврат. Сопоставлены токенные мотивы, локальная грамматика, части имён в интерфейсе и их комбинации. Это локальная эвристика по написанию и синтаксическим узлам. Межпроцедурный анализ и разрешение алиасов в неё не входят. [Реализация](bindings.py) · [Tree-sitter C++](https://github.com/tree-sitter/tree-sitter-cpp)

Для сравнения ранжирования выставили по 448 ложных срабатываний на всём тесте и, в отдельном расчёте, по 37 на коротком срезе. Порог ровно под этот бюджет использует тестовые метки для ретроспективной оценки. Порог для применения выбирался заранее на dev, его эффект приведён отдельно.

## Результат на отложенных проектах

При 448 FP базовый ранжировщик находит 2 374 положительных примера, F1 0,83650. На коротком срезе при 37 FP — 119, F1 0,66295. При заранее зафиксированном пороге база находит 2 372 и даёт 448 FP.

Для переранжирования внутри короткого среза глобальный контроль использует раздельные бюджеты коротких и остальных функций, 37 и 411 FP. В этой строке опорный результат — 2 373 TP при 448 FP. Переобучение с упором на пропуски повышало вес 1 625 коротких положительных примеров. Только 24 из них учитель уверенно пропустил в собственном fit. Оба контрольных запуска по одной эпохе стартовали с одного checkpoint, использовали одинаковые 1 201 батч и seed 42. В варианте с весами +1 глобальный TP складывается из 17 исправленных и 16 новых пропусков. 95%-й интервал изменения TP — от −15 до +17 по парному бутстрэпу файлов внутри каждого проекта с повторным уравниванием FP. [Переобучение](reweight/analysis.json) · [Интервалы](fixed_budget_intervals.json) · [Все 26 сравнений](results.csv)

У 6 из 71 уверенного пропуска в том же тесте есть побайтово совпадающий текст функции с противоположной меткой. Каждый такой положительный прогноз по одному тексту расходует FP на отрицательном двойнике. В исходном срезе таких случаев 3 из 388. Это проверка консистентности входов и меток. Она не устанавливает причину расхождения разметки. [Проверка совпадений](collision_audit.json)

## Конкурсная оценка

Признаки переобучены на официальном fit и испытаны с исходным конкурсным энкодером на 30 655 публичных функциях. Пороги выбраны на внутренней калибровке официального train. Признаки добавили медианные 1,08 с извлечения на RTX 4090 и понизили локальный балл с 0,95676 до 0,95657. Текстовый признак длины воспроизвёл их итоговые метки vulnerability (+7 правильных и +6 ложных срабатываний), а обученное объединение исходного и канонического проходов прибавило 2 правильных и 2 ложных. Прибавки балла у этих дешёвых вариантов около 0,00001 и меньше. Интервалы ΔF1 обоих пересекают ноль. [Таблица публичных прогонов](public_results.csv) · [Синтаксические признаки и длина](official/analysis.json) · [Объединение окон](fusion/analysis.json)

При текущем MAT F1 и вычислительной стоимости устранение всех 23 уверенных коротких пропусков компактной модели без роста FP дало бы 0,95713. Устранение всех 75 коротких пропусков дало бы 0,95797. При исправлении всех 825 публичных пропусков vulnerability и сохранении 643 FP локальный балл был бы 0,96957. При полном recall для 0,97 потребовалось бы не больше 612 FP либо улучшение MAT или стоимости. При фиксированной vulnerability и единственном текущем MAT FP достаточно вернуть 41 из 62 пропусков MAT для 0,97. Это арифметические сценарии на публичных метках. Для подачи выбран проверенный `selective` раунда 12 с 0,95675 локального балла. ## Воспроизведение

Запускать из корня `experiments_20261120`. Тяжёлые checkpoint, массивы вероятностей, активации и сырые данные хранятся в `Banana:/home/user/shared-task-experiments-20261120`. Используется окружение `.venv` и дерево версий Tree-sitter из [раунда 12](../round12/README.md). Все двоичные решения исследовательской ротации сохранены в CSV. Локально `python3 nlbse/round13/summarize.py` сверяет метрики с решениями и восстанавливает обе итоговые таблицы без GPU.

```bash
py=.venv/bin/python
r=nlbse/round13
$py $r/rotate.py partition
$py $r/discovery.py
$py $r/rotate.py fit --family unix
$py $r/rotate.py score --family unix --parts probe dev test
$py $r/rotate.py fit --family compact
$py $r/rotate.py score --family compact --parts probe dev test
for part in fit probe dev test; do
  $py $r/bindings.py cache --role "$part"
done
$py $r/bindings.py fit
$py $r/evaluate.py tune
$py $r/evaluate.py test
$py $r/redistribute.py
$py $r/activation.py tune
$py $r/activation.py test
for mode in matched focused; do
  $py $r/reweight.py fit --mode "$mode"
  $py $r/reweight.py score --mode "$mode" --part dev
  $py $r/reweight.py score --mode "$mode" --part test
done
$py $r/reweight.py compare
$py $r/budget_interval.py
$py $r/collision_audit.py
$py $r/official.py feature_fit
$py $r/official.py tune
$py $r/official.py public
$py $r/fuse.py fit
$py $r/fuse.py public
$py $r/limits.py
$py $r/summarize.py
```
