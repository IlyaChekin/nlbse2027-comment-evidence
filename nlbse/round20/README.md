## Что сработало

Вспомогательная голова компактного энкодера учит 19 индикаторов WeakSATD и их объединение. При исходной вероятности до 0,08 средняя точность ранжирования срабатываний правил выросла с 0,059 до 0,504 на отложенной группе A и с 0,051 до 0,400 на B. Голова с замороженным энкодером дала 0,064 и 0,063. На A отбор совместно обученной головой с той же настроенной долей запросов даёт 241 TP по правилам за 1 124 проверки. Отбор по исходной вероятности даёт 166 TP за 2 942 проверки. Порог отбора переносится между проектами, поэтому фактическое число вызовов может отличаться. Внутренняя калибровка предпочла прежний инструмент маршруту с дополнительным энкодером. [Группа A](test_a/study.json) · [Группа B](test_b/study.json) · [Официальная калибровка](official/policy.json)

Условный энкодер оценивает вероятность срабатывания правил и вероятность vulnerability отдельно для случая с точным срабатыванием и без него. Эти компоненты калибруются на файлах разработки. При запуске сначала вычисляется вероятность с учётом обоих исходов. Правила вычисляются, если исход с высокой вероятностью повлияет на решение около порога. В отобранной политике с дополнительным правилом на группах A и B получены **+309 и +37 TP** при прежнем FP каждого проекта. Фактически перепроверены 15 721 и 2 537 функций соответственно. Замороженный порог на отдельной внутренней проверке даёт +12 TP и −6 FP. ## Точное ускорение и дополнительный сигнал

Общий поиск известных имён функций использует один проход по строке и индекс имён. Старое сопоставление сохранено для шаблонов с регулярными выражениями. Буквальное совпадение сохраняет порядок, повторы имён и прежние разделители. Новый сканер повторил **4 077 134 из 4 077 134 значений правил** на 214 586 обучающих функциях. На одной и той же выборке 1 200 строк медиана одиночного запуска снизилась с 3,47 до 1,40 с. [Проверка счётчиков](scan_equivalence.json) · [Три парных времени](scan_timing.json)

В опубликованной реализации ещё одна проверка интерпретирует строку как выражение. В новой версии применяется только разбор ограниченных числовых литералов и остальные статические компоненты этой проверки. Срабатывания, которых нет у прежних 19 правил, отмечают 225 положительных и 2 отрицательных функций на A, 56 положительных и 2 отрицательных на B. Условный энкодер обучен на прежних 19 проверках. ## Воспроизведение

Установлены PyTorch с CUDA и Node.js 22. Пути, разбиения, контрольные суммы данных и веса зафиксированы в отдельных рецептах. Опции для селектора проверены на двух отложенных группах проектов. Включённая в итоговую политику конфигурация выбирается до публичного прогона.

```bash
export NLBSE_SCANNER_WORKERS=6 OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=2
py=.venv/bin/python
r=nlbse/round20
$py "$r/verify_scan.py" profile
$py "$r/verify_scan.py" verify
$py "$r/extended_counts.py"
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$r/student.py" "$part"
  $py nlbse/cuda_launch.py "$r/student.py" "$part" --factor
done
for part in test_a test_b; do
  $py nlbse/cuda_launch.py "$r/evaluate_rules.py" project --rotation "$part"
  $py nlbse/cuda_launch.py "$r/factor.py" collect --rotation "$part"
  $py "$r/factor.py" project --rotation "$part" --numeric
done
$py "$r/subsets.py" profile
$py "$r/subsets.py" profile --implementation numeric
$py nlbse/cuda_launch.py "$r/factor.py" tune --numeric
$py nlbse/cuda_launch.py "$r/factor.py" public --numeric
$py "$r/build_factor_release.py" factor_numeric
$py nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round20_factor_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$r/release_verification" \
  --entry "$r/predict_factor.py" --cuda-launch
python3 nlbse/round19/report.py "$r/factor_numeric"
```
