## Почему правила помогают

Организаторы строят метку vulnerability как объединение Devign, Big-Vul и метки W. Для W авторы MADE-WIC использовали проверки WeakSATD. Воспроизведены 19 отдельных проверок из опубликованных исходников и их обработка комментариев. Две позиции в исходном списке ведут к одной реализации, вызывающей вычисление произвольной строки. Она исключена из локального сканера. Читаются только файлы правил и инструкции. Вход инференса — текст `Function`. Результат измеряет согласие с конкурсной разметкой, часть которой получена из этих проверок. [Правила NLBSE](https://github.com/nlbse2027/code-comment-classification#dataset-preparation) · [Протокол MADE-WIC](https://arxiv.org/html/2408.05163v1#S2) · [Исходники и лицензия](https://zenodo.org/records/12567874)

Используются бинарные индикаторы и счётчики правил, логит модели и число сработавших правил. Калибровку отделили по исходным файлам. В проектных проверках разделы fit и calibration исключают совпадения по токенным отпечаткам. Отдельно сравнивали все функции и вызов правил в двух интервалах исходной вероятности.

| Вариант | A, 1 186 FP | B, 388 FP |
|---|---:|---:|
| Деревья по всем функциям, выбраны по проектной калибровке | +604 TP | +120 TP |
| Логистическая голова по всем функциям | +574 TP | +105 TP |
| Логистическая голова, сканируются исходные оценки от 0,08 до 0,96 | +393 TP | +67 TP |

В каждом проекте фиксируется собственное исходное число FP. Диагностическое сравнение пересчитывает порог по меткам оцениваемой группы. В таблице показаны разницы относительно исходного энкодера, также ранжированного внутри проекта. Независимая внутренняя калибровка официального fit выбрала третью строку с учётом CPU-времени. Там она вернула +33 TP при 100 FP. На отдельной внутренней проверке замороженный порог дал +46 TP и +6 FP. [Сравнение по разделам](project_results.csv) · [Замороженный выбор](official/policy.json)

## Воспроизведение

Закреплены исходные файлы 33 модулей и документации, 60 794 строки счётчиков и архив метрик. В проверке на первых 4 000 строках кэш описаний правил сохранил все 76 000 счётчиков. Кэш держит описания справочника в памяти на время процесса. При развёртывании версии с комбинированием сохраняются один энкодер и один маленький обученный логистический слой.

Команды из корня экспериментов на Banana. `NLBSE_NODE` указывает на Node.js 22.23.4 при запуске из сохранённой среды. В новом окружении можно задать обычный `node` из PATH. Все функции подаются локально в процесс. Для пересчёта таблиц из архивных CSV не нужны веса или GPU.

```bash
export NLBSE_SCANNER_WORKERS=6 OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2
py=.venv/bin/python
r=nlbse/round19/weak_satd
$py "$r/fetch_rules.py"
$py "$r/full_scan.py" heldout
$py "$r/replay.py" --rules "$r/heldout_parallel.csv"
$py nlbse/cuda_launch.py "$r/official.py" fit
$py nlbse/cuda_launch.py "$r/official.py" public
$py "$r/build_release.py"
$py nlbse/round12/verify_release.py nlbse/submission/NLBSE2027_round19_tool.zip \
  nlbse/data/raw/test-00000-of-00001.parquet "$r/release_verification" \
  --entry "$r/predict.py" --cuda-launch
python3 "$r/verify_replay.py"
python3 nlbse/round19/report.py "$r"
```
