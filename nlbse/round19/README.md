# NLBSE 2027 · перенос между проектами и проверка правил разметки

## Взвешивание обучающих семейств

Две ротации удерживают целиком 3 и 7 семейств проектов. В первой обучаются 160 035 функций из 8 семейств, во второй 180 019 функций из 4 семейств. Файлы калибровки отделены от fit. Копии функций между частями удалены по токенному отпечатку. Прежние контрольные веса обучались только на части Linux, которая входит в fit обеих ротаций. [Разбиения и версии](partition.json)

Продолжили обучение компактного энкодера на тех же строках и с одинаковым числом шагов. Контроль использует обычное среднее. Второе обучение повышает вес малых проектов пропорционально квадратному корню их доли. Третье дополнительно повышает вес проектов с большей сглаженной потерей. Вес применяется к vulnerability. Единственный проход и возможный повтор канонического вида используют прежнюю архитектуру. MAT-решения сверены на каждой строке. Сглаживание эксперимента основано на идее оптимизации риска по группам. [Sagawa et al.](https://arxiv.org/abs/1911.08731)

В таблице число положительных решений изменяется относительно исходного компактного энкодера. FP удерживаются отдельно для каждого проекта. Общий бюджет равен 1 186 FP на A и 388 FP на B.

| Продолжение обучения | A, seed 42 | A, seed 101 | B, seed 42 | B, seed 101 |
|---|---:|---:|---:|---:|
| Обычное среднее | −16 | −24 | +1 | −6 |
| Баланс по семействам | −28 | +6 | +1 | −11 |
| Повышение веса трудных семейств | −36 | −19 | −1 | −11 |

Когда FP закреплены только в сумме, повышение веса трудных проектов на A даёт −40 и +18 TP относительно исходных весов, против −76 и −87 у обычного дообучения. Это позволяет перераспределить ошибки между проектами. При бюджете каждого проекта изменение относительно обычного дообучения составляет −20 и +5 TP. [Прогнозы и таблица](project_results.csv) · [По каждому проекту](project_results_by_project.csv)

На калибровке официального fit сбалансированный вариант дал 0 TP при 22 FP и +2 FP на независимой проверке. Выбран исходный энкодер. Три публичных прогона воспроизвели прежние решения на 30 655 функциях, дали 14 886 GFLOPs и локальный балл 0,957807. Ранее зафиксированный лучший парный замер 0,957863. [Внутренний выбор](official/policy.json) · [Замер](public_results.csv)

## Цель 0,97

С прежней MAT и стоимостью даже восстановление всех 701 пропусков vulnerability при 700 FP дало бы 0,968676. Если убрать 100 FP, для 0,97 нужно вернуть 696 из 701 пропуска. Если убрать 500 FP, нужно вернуть 319. [Требуемые сочетания TP и FP](target_frontier.csv)

Соревновательная голова при обучении без информации о проекте получает ту же архитектуру. Дополнительная голова пытается распознать семейство из представления функции отдельно для каждого класса vulnerability. Энкодер получает обращённый градиент этой головы. При инференсе используются только веса компактной модели. Результат при FP, фиксированных отдельно для каждого проекта, составляет +4 и −24 TP в A, −6 и −6 в B. [Ganin et al.](https://jmlr.csail.mit.edu/papers/v17/15-239.html) · [Предсказания](adversary/project_results.csv)

Усреднение весов нескольких продолжений сохраняет один комплект весов и действующую архитектуру. Среднее из восьми обучений с весом 0,40 у исходного checkpoint даёт −1 и 0 TP при прежнем FP каждого проекта в A и B. При общем бюджете результат −7 и +4 TP. [Сравнение весовых смесей](merged/project_results.csv)
