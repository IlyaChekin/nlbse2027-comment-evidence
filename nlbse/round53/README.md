# NLBSE 2027 · маска внешней разметки в общем энкодере

Линейная голова раунда 51 лучше ранжировала историческую Big‑Vul/Devign после исключения строк без этой разметки. Здесь маска применяется при обучении последних двух локальных блоков, глобального внимания и дополнительной головы компактного энкодера. Варианты получают одни и те же функции из официального train, инициализацию, веса классов, два прохода по данным и регуляризацию относительно исходных логитов маршрутизации. Первый вариант оптимизирует только `vulnerability`. Второй добавляет `W` и Big‑Vul/Devign для всех однозначно сопоставленных функций. Третий использует те же `W`, но вычисляет вклад Big‑Vul/Devign только на строках с явно присутствующей исторической разметкой. [Данные и маска](../round51/support/receipt.json)

Отбор сопоставляет число TP при прежнем FP и число снятых FP при прежнем TP каждого проекта. Контроли включают перенос порога текущей модели и вариант без исторической разметки. Вариант с маской сравнивается также с полной разметкой. Один порог из калибровки применяется к review. Дополнительно измеряется F1 на 200 строках review с путями, которых не было в исходном fit. Для кандидатов, прошедших отбор, выводы повторяются с фактической маршрутизацией, затем измеряются пять пар публичных прогонов. MAT использует канонический разбор из подтверждённого архива.

| Проверка | AP Big‑Vul/Devign по всем сопоставлениям | AP с маской явной разметки | AP Big‑Vul/Devign без W, до → после |
|---|---:|---:|---:|
| A, 25 950 явно размеченных функций | 0,12085 | 0,15082 | 0,08865 → 0,10048 |
| B, 3 644 явно размеченных функций | 0,11317 | 0,12501 | 0,09136 → 0,10143 |
| Внутренний review, 853 явно размеченные функции | 0,52720 | 0,53701 | 0,57176 → 0,58472 |

Из 756 настроек три прошли числовой отбор. Эти настройки относятся к двум вариантам, контролю по `vulnerability` и совместному обучению на всех сопоставлениях. Ни одна настройка с маской явной разметки не прошла числовой отбор. На фактическом конвейере оба оставшихся варианта потеряли по два TP и сняли по одному FP на review. На калибровке контроль вернул один TP и снял два FP за два дополнительных запроса, совместная голова потеряла два TP, сняла один FP и потребовала шесть дополнительных запросов. Сквозной запуск выявил изменения маршрута вместе с расхождением в решениях. До публичного замера варианты не дошли. ## Воспроизведение на Banana

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 TOKENIZERS_PARALLELISM=true RAYON_NUM_THREADS=4 NLBSE_SCANNER_WORKERS=6
export NLBSE_NODE="$PWD/nlbse/round19/weak_satd/runtime/node"
py=.venv/bin/python
r=nlbse/round53
for part in test_a test_b official; do
  $py nlbse/cuda_launch.py "$r/train53.py" "$part"
  $py nlbse/cuda_launch.py "$r/eval53.py" "$part"
done
$py "$r/eval53.py" select
$py nlbse/cuda_launch.py "$r/live53.py"
```
