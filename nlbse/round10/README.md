# NLBSE 2027 · компактный энкодер, полные комментарии и глубина

Проверили альтернативу асимметричному каскаду CodeT5+ из раунда 9. Функцию обрабатывает один многозадачный энкодер с двумя логитами. Два кандидата различались предобучением, токенизатором и размером. У CodeT5-small шесть исходных блоков и скрытая размерность 512. У UniXcoder-base-nine шесть блоков с индексами 0, 2, 4, 6, 8, 10, скрытая размерность 768 и префикс `<encoder-only>`. Оба видят до 512 токенов и пять признаков длины и тегов из полных комментариев. [CodeT5-small](https://huggingface.co/Salesforce/codet5-small/tree/b1ee9570c289f21b5922b9c768a1ce12957bf968), [UniXcoder-base-nine](https://huggingface.co/microsoft/unixcoder-base-nine/tree/5f0dc256eb0904af496d427451da5d7f90261676), [требования NLBSE](https://nlbse2027.github.io/tools/).

**Для конкурсного балла выбран `compact_lexical_deferred`.** 19 589 функций из 30 655 заканчивают после четырёх блоков. Относительно прежнего balanced расчётные операции сократились на 50,8%, сквозная медиана на RTX 4090 — с 9,55 до 8,80 с. Средний F1 изменился на −0,12 п.п. при парном 95%-м интервале −0,37…+0,14 п.п. F1 по vulnerability снизился на 0,42 п.п. Ускорение подготовки входа вычисляет смещения токенов по запросу только для строк с возможным тегом. Все 61 310 решений исходного компактного каскада сохранены. [Замеры](compact_exit/lexical_deferred/analysis.json), [контроль смещений](offset_bench.json).

**Максимальный средний F1 даёт `unix_lexical`.** Прирост к прежнему quality равен +0,284 п.п., парный 95%-й интервал +0,086…+0,456 п.п. После исключения 251 публичной строки с точным совпадением текста в официальном train средний F1 равен 0,93618 против 0,93333. Этот выигрыш связан с vulnerability. [Проверка по файлам и с удалением дублей](comparison.json), [публичные прогнозы](unix_context/unix_lexical/predictions.csv).

**Почему сработали полные комментарии.** У компактной модели гибридная голова MAT восстановила 15 истинных положительных решений без новых ложных срабатываний. В 14 из этих функций тег находился за границей 512 токенов. На UniXcoder восстановлены 9 истинных положительных, у всех 9 тег находился за границей. Лексическая голова дала 0,93361 MAT F1 на обоих энкодерах. Этот результат относится к конкурсной разметке MAT. Результаты с независимой разметкой SATD описаны отдельно. [Разбор CodeT5-small](student_context/analysis.json), [разбор UniXcoder](unix_context/analysis.json), [независимая разметка](../round7/README.md).

Промежуточная глубина исходного CodeT5+ дала 0,93078 F1 и 0,92809 локального балла в выбранном каскаде. Модель с фиксированным пятым блоком и выборочным шестым дала 0,93242 F1. На внутренней проверке регрессор ожидаемой пользы и пороги, зависящие от длины, уступили balanced. [Все режимы в CSV](results.csv), [глубина](depth_public/analysis.json), [регрессор](risk_frozen/policy.json), [контроль длины](length_gate.json).

## Протокол

- Оба кандидата обучались два прохода по одинаковым 193 100 официальным строкам fit. Использованы взвешенная BCE и мягкие цели замороженного CodeT5+ из раунда 9 с температурой 1,7. Одинаковые seed 42, AdamW, dropout 0,12 и weight decay 0,01. Скорости обучения энкодера и голов 3e−5 и 1,4e−4, warmup 5%. Веса классов ограничены пятью. Прогнозы учителя сохранены по исходным номерам строк. [Данные и хеши](../data/manifest.json), [параметры запуска](students.py), [происхождение целей](teacher.json).
- Исходные пороги и эпоха выбраны на 4 292 строках калибровки. Для новых голов использованы 12 900 отдельных строк, для внутренней проверки ещё 4 294. Совпадающие тексты сгруппированы до разбиения. Правила зафиксированы перед публичной оценкой. [Разбиение](../round8/frozen/holdout.npz).
- Все публичные результаты относятся к одним 30 655 строкам организаторов. Время измерено на RTX 4090, под FP16. Формула использует средний F1, время forward и аналитическую оценку GFLOPs. Парные 95%-е интервалы получены из 2 000 пересэмплирований групп `(Projectname, Filepath)`. [Исходная формула](../score_runtime.py), [сравнение прогнозов](summarize.py).

## Контроли

- Для CodeT5+ проверили промежуточную глубину после исходного четырёхблочного префикса. Сравнили обычный пятый блок, последний блок с пропуском пятого и пятый блок с обновлением половины токенов в шестом. Выходные головы обучались на замороженных представлениях. Правило выбора проверялось на тех же внутренних группах. [Промежуточная глубина](depth.py).
- Для CodeT5-small сравнили eager и fused attention с тем же относительным позиционным смещением. Отдельный скалярный readout MAT использует один логит энкодера и признаки полного комментария. Внутренняя калибровка сравнивает наличие тегов, количество и положение за границей окна. Выбор по MAT F1, затем по average precision на калибровочных строках. Признаки границы вычислены по смещениям токенизатора. Лексический контроль использует те же признаки комментария и обходится без логита MAT. Прогноз vulnerability берётся из общего энкодера. [Контроль комментариев](student_context.py).
- Для раннего выхода CodeT5-small обучена логистическая голова vulnerability по состояниям после четвёртого блока. Сомнительные функции и все функции с обнаруженным тегом требуют ещё двух блоков. Уже рассчитанные состояния переиспользуются. В раннем выходе MAT даёт лексический readout. Контроль `--lexical` сохраняет то же правило маршрутизации и даёт этот readout всем функциям. [Каскад](compact_exit.py).

## Воспроизведение

Используйте Python 3.11 или 3.12 и CUDA-сборку PyTorch 2.8.0. Загрузите два parquet по URL из `nlbse/data/manifest.json` и сверьте SHA-256. В архиве `nlbse/data/split_manifest.csv.gz` содержит зафиксированное разбиение. Учитель для `students.py` прилагается как `teacher.npz`. Исходные веса подгружаются только для повторного обучения.

```bash
gzip -dc nlbse/data/split_manifest.csv.gz > nlbse/data/split_manifest.csv
export TOKENIZERS_PARALLELISM=false OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=3
bash nlbse/round10/fetch_backbones.sh
for family in t5_small unixcoder9; do
  python3 nlbse/round10/students.py fit "$family"
  python3 nlbse/round10/students.py tune "$family"
  python3 nlbse/round10/students.py public "$family"
done
python3 nlbse/round10/student_context.py tune
python3 nlbse/round10/student_context.py public
python3 nlbse/round10/student_context.py tune --family unixcoder9
python3 nlbse/round10/student_context.py public --family unixcoder9
python3 nlbse/round10/compact_exit.py tune
python3 nlbse/round10/compact_exit.py public
python3 nlbse/round10/compact_exit.py public --lexical
python3 nlbse/round10/compact_exit.py public --lexical --deferred-offsets
python3 nlbse/round10/summarize.py
```

Для контроля `depth.py` нужен замороженный CodeT5+ из [полного пакета раунда 9](../submission/NLBSE2027_round9_tool.zip). В команде выше уже используются сохранённые публичные таблицы этого контроля. Воспроизведение всех сравнений времени требует запускать GPU-команды последовательно.
