## Какие признаки проверили

- **Фразы техдолга.** В комментариях из fit удалены слова с маркером и варианты с внутренними разделителями. Положительный сигнал обучен на 1 636 фразах из 1 551 функции с явным маркером. В контроле используются целые комментарии с тем же удалением. Сравнены словные биграммы и символьные n-граммы, отдельные фразы и целые комментарии, всего четыре варианта. Сравнение учитывает 4 245 фраз без маркера из положительно размеченных функций. Для каждого входа берётся максимум оценки среди его фраз или комментариев. В Chromium лучший диагностический порог до первого возврата допускает 2 FP. На B лучший диагностический вариант требует 35 FP для первого возврата в radare2. При замороженных порогах по обоим наборам получено 0 TP и от 0 до 6 дополнительных FP в одной группе. [Разметка и пороги](policy.json) · [Сравнение вариантов](comparison.csv) · [Цена первого возврата](results.json)
- **Синтаксис без имён.** Дерево C/C++ преобразовано в счётчики типов узлов, рёбер, троек предок–родитель–узел и соседей. Признаки объявления и тела подаются раздельно и вместе. Содержимое идентификаторов, строк и комментариев не участвует. Обычный классификатор обучен на 241 пропуске с подтверждённым маркером прямо перед функцией и 1 393 контролях из тех же файлов Linux. Попарная версия использует 1 332 пары для 230 пропусков из этой группы. Варианты не вернули ни одного пропуска при замороженных порогах. Лучшие диагностические пороги до первого возврата требуют 62 FP на A (FFmpeg) и 3 на B (radare2). Среди пропусков без комментариев в Firefox цена первого возврата составила 11 FP. [Настройки и версии](syntax/policy.json) · [Сравнение вариантов](syntax/comparison.csv) · [Цена первого возврата](syntax/results.json)

## Сверка с публичными ошибками

Решение раунда 34 имеет **444 TP, 0 FP и 61 FN MAT**, F1 MAT **0,935722**. Среди 61 пропуска у 30 функций нет видимого комментария и подтверждён пропавший исходный маркер, ещё у 11 во входе видны другие комментарии, а помеченный отсутствует. Публичные исходные сверки повторно объединены по ID и сопоставлены с сохранёнными результатами раунда 34. Исходники участвовали только в аудите происхождения и выборе обучающих пар из fit. Публичный набор не запускался с новыми MAT-ветками после провала нулевого FP на проектах. [Два непересекающихся списка](../round18/mat_residual/source_audit_public.json) · [Случаи с другими комментариями](../round26/mat/visible_provenance.json) · [Сводный аудит](audit.json)

При неизменных затратах и решениях vulnerability до **0,97** достаточно вернуть **17 MAT** без новых ложных срабатываний. Гипотетическое исправление всех 20 случаев с пока не установленным происхождением дало бы **0,971063**. Это расчёт по меткам и старому времени. Подтверждённый локальный балл остаётся **0,964473**. ## Воспроизведение

Запуск из корня экспериментов на Banana. Файлы parquet закреплены в `nlbse/data/manifest.json`. Группы закреплены в `nlbse/round13/partition.npz`. Политики, веса, оценки и бинарные решения сохранены рядом с отчётом. Установка парсеров нужна только для синтаксического опыта.

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2
py=.venv/bin/python
path=nlbse/round36
$py -m pip install --target "$path/vendor" -r "$path/syntax_requirements.txt"
$py "$path/comment_signal.py"
$py "$path/syntax_signal.py"
$py "$path/audit36.py"
```
